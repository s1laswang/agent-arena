# DIFFICULTY: is the judged instruction fair? (PLAN-95 B4 instruction audit)

**Question.** When a frontier agent loses on Canary, is that because it reasoned badly, or because the instruction tricked it, hid a rule, set an impossible clock or gave it a broken tool?

**Short answer.** No hidden rule changes who the mole is, no tool is broken, and the clock is feasible: the reference solver scores +0.743 / +0.594 / +0.563 (easy / medium / hard) with the same tools and text ([`results/anticheat/exploits.md`](../results/anticheat/exploits.md)). The audit did find **gaps in how the rules are worded**: the order of events within a day, how the careful mole weighs canaries, the access-log model, what messages contain, and a few cosmetic artifacts. Each gap is stated below with the code that settles it. The text changes are proposed to the CEO (P1–P10), since `canary/env.py` is frozen and not ours to edit. Nothing here was fixed in code.

## What was audited
- **The judged text:** `canary.text.instruction.render(tier)` (= `Env(tier, 0).instruction()`) for easy, medium and hard, plus the Harbor preface that `harbor/build.py` puts in front of it, plus the MCP tool list (`Env.tools_spec()`). `harbor/canary-task/instruction.md` is the medium render, byte-identical apart from a trailing newline.
- **Pass 1, by hand (integrity engineer):** every sentence checked against `canary/env.py`, `canary/world.py`, `canary/mole/dsl.py` and `canary/rules.py`. All 13 tools were smoke-tested on hard (dev seed 4242): `status`, `list_employees`, `list_documents`, `read_access_logs`, `search_messages`, `read_message`, `interview`, `plant_canary`, `check_leak_feed`, `restrict_access`, `unrestrict_access`, `advance_day`, `accuse`. All returned `ok: true` with the documented fields.
- **Pass 2, gemini-4-carbon:** one audit pass through the repo's Gemini client, `scripts/instruction_audit.py`. The model saw only what the agent sees (no source code). Its raw output is [`results/audit/instruction_audit_gemini.md`](../results/audit/instruction_audit_gemini.md): 9 findings, verdict "not quite ready to publish as-is". The first call at the model's default thinking level spent its whole 16k output cap on thoughts and returned no text ($0.17), so the pass was re-issued once at thinking=low with a 32k cap ($0.07). Total spend: about $0.25, 2 API calls.
- Every Gemini claim below was checked against the code. Where the code shows that the text is accurate, the severity is lowered and the reason given.

## Findings

"Status" is one of: **by design** (with the reason), **proposed to CEO** (a text change, not made by us), or **fixed** (none in this audit).

## Proposed text changes, for the CEO (not applied: `canary/env.py` is frozen)
All of these are wording changes to `Env.instruction()` (plus one schema tweak in P7). None changes a rule, a number, the solver or any score. `tests/test_env_docs.py::test_instruction_md_matches_generator` would need `harbor/canary-task/instruction.md` regenerated afterwards.

- **P1 (D1, hard):** after "Canaries are level 1, so every employee may receive one.", add "Clearance has no other effect."
- **P2 (D2, base tiers):** replace "The default mole leaks a random document and does no extra framing, exactly as described above." with "In this tier the mole uses only the default rule: it leaks a random eligible document (weighted as above) and does no extra framing."
- **P3 (D3, careful tiers):** replace the careful sentence with "This mole is careful: each eligible document has weight 1, except a canary, whose weight is 1 − (the share of all employees who received any variant of it); it picks one document in proportion to these weights. A canary sent to everyone is never picked." Replace "The mole never knows which documents are canaries." with "Apart from that weight, canaries are treated like any other document."
- **P4 (D5, hard):** append "If only one label was planted, that label is always shown."
- **P5 (D6):** "Every employee who holds documents makes a random number of accesses per day in total, not per document (Poisson, average X for an innocent employee and Y for the mole); each access is to a random document it holds."
- **P6 (D8):** add under Days: "Order of events: day d's new documents go out at the start of day d. When you call `advance_day` on day d: (1) the mole may leak a document it received on days d−2..d; (2) restriction costs are charged; (3) day d's access logs and messages are created; then day d+1 starts. A leak at the end of day d with delay k appears in the feed from day d+k on."
- **P7 (D9, D15):** change the `list_documents` description to "List published documents with their recipients (and variants for canaries) in an inclusive day range."; change `search_messages` to "... (the first 20 matches in day order)"; add `minLength: 1` to `query`; add "Messages for a day appear when that day ends." Optional, as a difficulty call: "Messages are written from public facts only."
- **P8 (D10):** when `p_single_dept_recipients` is 0, print "Every regular document goes to everyone in two randomly chosen departments." and annotate `noise: 1 (no change)`.
- **P9 (D11):** "Different topics, or the same topic on different days, are independent draws with the same probabilities."
- **P10 (D12, D16):** write "true V" in the EV formula, and use "Your Nth call is your last; unless it is `accuse`, the episode then ends with score 0."

## How this relates to the failure story
None of the findings explain the frontier agents' measured losses on their own. The losses tagged so far are premature accusation, never abstaining, and ignoring the delays; that last one is stated in plain numbers on every tier ("after a delay of 2 or 3 day(s)"). The strongest candidates for text-induced error are D8 (order of events) and D3 (careful weight). P6 and P3 would remove them without changing a rule. The B1 hint ablation (an opt-in `ev_delay` hint; see docs/PLAN-95.md) is the causal test: if spelling out the decision rule and the delays moves Gemini toward the solver, the information was always sufficient and the failure is the decision.
