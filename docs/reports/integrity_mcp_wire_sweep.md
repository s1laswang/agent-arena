## 4. Threat Model Analysis

### 4.1 Parallel Races and Episode Lock Serialization (`W01`-`W05`, `J1`, `J8`)
- `Episode.call` and `Episode.ledger_payload` execute under a single `threading.Lock` (`canary/mcp_server.py:250,273,281`), serializing calls from arbitrary concurrent MCP sessions and TCP connections.
- **Daily canary and action caps (`W01`, `W02`):** A 16-thread `threading.Barrier` race against `plant_canary` accepts `1/1` on `easy`/`medium` and `2/2` on `hard`/`hard_forge`, rejecting the remaining threads with `"canary limit for today reached"` and matching the ledger's `canary_planted` count (`W01`). Racing 16 investigative calls accepts `8/8`, rejects `8` with `"daily action limit; call advance_day"`, and cleanly restores `8` actions after `advance_day` (`W02`).
- **Interleaved restrictions and `V` accounting (`W03`):** Racing `restrict_access`, `unrestrict_access`, `status`, and `advance_day` across 16 sessions keeps `0.0 <= V <= 1.0` at every step; independent reconstruction of `V` from the final ledger events (`canary_planted`, `leak`, `restricted`, `unrestricted`, closed days) matches `led["V"]` within `1e-9` on `32/32` runs.
- **Global `tool_call_cap` cliff (`W04`):** Padding to 6 calls before the global `tool_call_cap` and racing 8 `status` + 8 `accuse` threads always terminates with exactly one `episode_end` entry: either `end_reason == "accused"` with `len(accs) == 1` or `end_reason == "tool_cap"` with `len(accs) == 0` and `score == 0.0`.
- **Session deletion persistence (`W05`):** Episode state lives on `Episode`, not on individual MCP sessions. Terminating `Mcp-Session-Id` via `DELETE /mcp` invalidates that session (`HTTP 404` thereafter) while preserving planted canaries, restricted employees, `V` deductions, and consumed daily actions for subsequent sessions.

### 4.2 JSON-RPC Batches, Methods, Versions, and Request IDs (`W08`, `W14`, `W16`, `J3`)
- **JSON-RPC batches and concatenated payloads:** Streamable HTTP `POST /mcp` rejects JSON-RPC batch arrays (`[{"jsonrpc":"2.0",...}]`, `J3` -> `HTTP 400`) and back-to-back concatenated JSON objects (`{...}{...}`, `W14` -> `HTTP 400`), preventing multi-accusation batching in one HTTP body.
- **Non-tool MCP methods (`W16`):** Calling `resources/list`, `resources/read`, `prompts/list`, `prompts/get`, `roots/list`, `completion/complete`, or forged `admin/reset` / `ledger/get` RPC methods returns JSON-RPC errors (`unexpected_method_ok=0`).
- **Protocol version & typed IDs (`W08`, `W16`):** Unsupported `MCP-Protocol-Version: 1999-01-01` is rejected (`HTTP 400`). Extreme or non-scalar `id` values (`null`, `""`, `-999`, `2^53 + 1`, 2 KB string, object, array, `NaN`, `Infinity`, `-0.0`, `1e309`) produce `0` HTTP 500s and `0` unauthenticated tool executions.

### 4.3 Duplicate Keys, Unicode Escapes, NUL Bytes, and Oversized/Deep JSON (`W06`-`W10`, `J2`, `J5`)
- **Single-validator architecture:** `canary.mcp_server` uses low-level `mcp.server.Server` rather than FastMCP/Pydantic signature coercion, passing the parsed `arguments` dict directly to `Env.call`. There is no schema-coercion mismatch between transport and `Env`.
- **Unicode-escaped and duplicate keys (`W06`, `W07`):** Escaped keys (`\u0065mployee`, `\u0073core`, `\u0063orrect`, `\u006dethod`) decode once in `json.loads`; `Env` rejects extra keys (`score`, `correct`) with `ok=False` (`accepted_accuse=0`). Duplicate object keys in `plant_canary` collapse to last-key-wins in `json.loads` *before* `Env` validates restricted employees and `max_variants=3`, blocking 4-variant smuggling (`bad_accepted=0`) and multi-variant per-employee assignments (`collapsed_single_variant=True`).
- **NUL bytes and homoglyphs (`W09`, `W10`):** Escaped `\u0000`, Cyrillic `\u043500`, and zero-width `\u200b` employee/message IDs fail strict roster validation; unescaped raw `0x00` bytes inside JSON strings fail RFC 8259 parsing (`HTTP 400`); 13 boundary/type-confusion `plant_canary` payloads (`W10`) are `0/13` accepted with `V=1.0` unchanged.
- **Oversized and deeply nested JSON (`J5`):** A 5 MB `search_messages` argument, 20,000-deep nested `[` array (`HTTP 400`), and invalid UTF-8 bytes (`\xff\xfe`, `HTTP 400`) are rejected without crashing `uvicorn` or breaking active sessions.

### 4.4 HTTP Smuggling, Framing, Content Negotiation, and DNS Rebinding (`W13`-`W15`)
- **Chunked framing and abrupt disconnects (`W14`):** Multi-chunk `Transfer-Encoding: chunked` valid JSON succeeds (`HTTP 200`), chunked truncated JSON returns `HTTP 400`, empty bodies return `HTTP 400`, and mid-chunk / truncated `Content-Length` TCP drops do not wedge the event loop or affect active sessions.
- **Media-type enforcement (`W13`):** `POST /mcp` with `text/plain`, `application/x-www-form-urlencoded`, `multipart/form-data`, or missing `Content-Type` returns `HTTP 400`/`415`; omitting `text/event-stream` from `Accept` returns `HTTP 406`.
- **Method and DNS-rebinding guards (`W15`):** `PUT`, `PATCH`, and `OPTIONS /mcp` return `HTTP 405`; `HEAD /ledger` returns `405` with an empty body; `Host: evil.attacker.invalid` (`HTTP 421`) and `Origin: http://evil.attacker.invalid` (`HTTP 403`) are blocked by transport-layer DNS-rebinding protection.

### 4.5 Session Forgery and Streamable HTTP Lifecycle (`W11`, `W12`, `J11`)
- `DELETE /mcp` and `GET /mcp` enforce `Mcp-Session-Id`: missing header -> `HTTP 400`, forged or already-deleted session ID -> `HTTP 404` (`W11`, `W12`).
- `GET /mcp` SSE requires `Accept: text/event-stream` (`HTTP 406` otherwise) and rejects concurrent duplicate SSE listeners on the same `Mcp-Session-Id` with `HTTP 409 Conflict` (`W12`).

### 4.6 `/ledger` and `/admin/reset` Auth, Redaction, HMAC, and Post-Accuse Parity (`W17`-`W20`, `J6`, `J9`)
- **Constant-time token auth (`W17`, `W19`):** `_token_ok` checks `bool(expected)` and `hmac.compare_digest`. Unset tokens always return `403`. All 16 `/ledger` query-pollution, URL-encoded NUL/space/non-UTF8, cross-token (`admin_token` on `/ledger`, `ledger_token` on `/admin/reset`), path-param (`/ledger;token=...`), and proxy-header (`X-Forwarded-For`, `X-Real-IP`, `X-Original-URL`, `X-Rewrite-URL`, `Authorization: Bearer`, `Cookie`) probes returned `403`/`404` with zero leaked fields.
- **Mid-episode redaction & HMAC-SHA256 signing (`W18`):** Even with a valid `ledger_token`, mid-episode `GET /ledger` omits `V`, `final_day`, `accused`, `correct`, and `accused_correct`, returning `ledger: []`, `score: 0.0`, and `redacted: "episode in progress"`. Both mid-episode and completed ledgers carry `HMAC-SHA256` signatures (`sign_ledger`); mutating `score`, `V`, `accused`, or `correct` fails `verify_ledger`.
- **Cross-tier reset & leak audit (`W19`, `W20`):** `POST /admin/reset` rejects dev seeds (`seed=7` -> `HTTP 400`), unknown tiers (`400`), non-integer seeds (`400`), and malformed JSON (`400`). Valid cross-tier resets rotate the opaque 16-hex `episode` token on every reset (`4/4` unique) and leak `0` occurrences of `seed`, `tier:seed`, `ledger_token`, `admin_token`, `ledger_key`, or `world_secret` in `instructions`, `tools/list`, `status`, or `list_documents`.
- **Post-accuse parity (`J9`):** Comparing a correct (`+1.00`) vs wrong (`-1.00`) accusation over MCP across `accuse` and subsequent post-end tool calls (`status`, `advance_day`, `check_leak_feed`, `list_employees`, `list_documents`, second `accuse`) produces byte-for-byte identical agent-visible responses after normalizing the target employee ID.

### 4.7 Linux `/proc` Hygiene, Unlinked `0600` Secret Files, and `BOOT_FD=73` Fail-Closed (`W21`-`W24`)
- **Secret file consumption & `os.execve` scrub (`W21`):** With `CANARY_CONSUME_SECRET_FILES=1`, `canary.mcp_server` reads and unlinks all five `0600` files (`CANARY_EPISODE_FILE`, `CANARY_WORLD_SECRET_FILE`, `CANARY_LEDGER_TOKEN_FILE`, `CANARY_ADMIN_TOKEN_FILE`, `CANARY_LEDGER_KEY_FILE`), writes the config into an anonymous `memfd_create("canary-cfg")` on `BOOT_FD=73`, strips all `SECRET_FILE_VARS`, `PLAIN_SECRET_VARS`, and `CANARY_CONSUME_SECRET_FILES` before `os.execve`, and closes fd 73 prior to listening. Live `/proc/<pid>/{environ,cmdline,fd,fdinfo}` inspection across all 4 tiers confirmed `files_deleted=True`, `fd73_closed=True`, `bad_fds=0`, `env_leaks=0`, `cmd_leaks=0`, and `log_leaks=0`.
- **Bootstrap spoofing & fail-closed startup (`W22`-`W24`):** Setting `CANARY_BOOTSTRAPPED=1` without fd 73 fails closed even when plain `CANARY_TIER`/`CANARY_SEED`/`CANARY_LEDGER_TOKEN` env vars are present (`W22`, no fallback to `load_config`). Passing empty, invalid-UTF8, `{}` incomplete, or dev-seed (`seed=7`) payloads on fd 73 fails closed (`W23`). Missing, whitespace-only, invalid-JSON, or `<16`-byte `CANARY_WORLD_SECRET_FILE` inputs under `CANARY_CONSUME_SECRET_FILES=1` exit with code `2` and never echo secret contents to stdout/stderr (`W24`).

## 5. Report-Only Observations (Zero Exploit Impact, Optional Hardening Notes)

Per squad rules, `canary/mcp_server.py` was not modified. Four non-exploitable protocol/process observations are recorded for maintainer visibility:

1. **Bootstrap failure exit code uniformity (`W22`, `W23`):** `canary/mcp_server.py:432` catches `(SeedNotAllowed, ConfigError, ValueError)` to return exit code `2`, whereas spoofed `CANARY_BOOTSTRAPPED=1` without fd 73 raises `OSError` (`EBADF`, exit code `1`) and incomplete `{}` on fd 73 raises `KeyError` (exit code `1`). Both terminate before `Episode` or `uvicorn` starts with zero secret echo; catching `(OSError, KeyError, TypeError)` alongside `ValueError` would standardize all invalid bootstrap exits to `2`.
2. **Float/NaN JSON-RPC `id` falls back to `JSONRPCNotification` (`W08`):** Python `json.loads` accepts bare `NaN`/`Infinity`/`-Infinity` (`allow_nan=True`). When sent as JSON-RPC `"id"` (`NaN`, `Infinity`, `-0.0`, `1e309`), Pydantic rejects `JSONRPCRequest` (`id: int | str`) and matches `JSONRPCNotification` in the `JSONRPCMessage` union, returning `HTTP 202 Accepted` while ignoring the `tools/call` without executing it (`accs=0`, `done=False`). Tool arguments themselves reject `NaN`/`Infinity`/`float`/`bool` strictly inside `Env`.
3. **Aborted SSE chunk framing on concurrent `DELETE /mcp` (`W05`):** When `DELETE /mcp` races an active `POST /mcp` on the same `Mcp-Session-Id`, the session transport closes mid-stream (`IncompleteRead` on the client socket), while `Episode._lock` preserves full `Env` atomicity and cost persistence.
4. **Multi-parameter `token` query handling (`W17`, `W19`):** Starlette `request.query_params.get("token")` evaluates the last repeated parameter (`?token=<valid>&token=wrong` -> `403`). This cannot bypass auth without already knowing the secret token, though rejecting `len(request.query_params.getlist("token")) != 1` would enforce strict single-parameter queries.
